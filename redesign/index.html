Guides section

01

Wayfinding

recommended — smallest change, biggest gainOpen mockup →

An evolution of what exists today. The index keeps its grouped structure but moves from bare hairline rows to cards that carry real metadata (steps, time, tooling) and a chip marking the two standalone pages. The guide page gains a sticky left rail: numbered step table of contents, reading progress, and prev/next guide navigation.

  • card shelf
  • step rail + progress
  • prev / next
  • fits current Section/Rows system
 02

Docs console

Open mockup →

Treats guides as technical documentation rather than marketing pages. The index becomes one dense, filterable table (slug, summary, track, step count) with a search field aimed at commands and role names. The guide page adopts the classic three-column docs layout: persistent guide nav on the left, content in the middle, "on this page" plus an edit-on-GitHub link on the right.

  • search + filters
  • 3-column docs layout
  • persistent nav
  • best when guide count grows
 03

Paths

implemented — now live in the appOpen mockup →

Reorganizes guides around intent instead of topic: Trader, Operator, Builder journeys with ordered milestones. The index is a set of path cards with progress dots (stored client-side); each guide gets a sticky path strip showing where it sits in the journey, giant outlined step numerals, "mark step done" check-offs, and prev/next along the path.

  • role journeys
  • local progress tracking
  • milestone strip
  • lib/guides/paths.ts
